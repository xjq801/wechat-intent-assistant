## 已实现

| 方向 | 现在的行为 |
|---|---|
| 完整需求整理 | 整理地点、时间、人数、预算、交通方式、菜系和忌口等字段。缺少必要信息时显示具体缺项；未提供的信息保持为空。 |
| 多轮修改与任务状态 | 继续聊天可修改现有需求；保留未修改的条件。支持取消、完成、新安排；多人意见矛盾会提示确认，兼容的忌口可合并。 |
| 可编辑需求卡片 | 右侧可直接修改字段。先保存、核对，再确认生成方案。正在分析新消息时暂停旧卡片确认，避免按过时条件生成。 |
| 主动询问与自动识别开关 | “自动整理本群需求”可关闭。点击“询问 AI”或使用 `@AI` 主动提问；回答问题不会自动改动需求卡片。 |
| 多方案比较 | 生成 2–3 个方案，展示匹配理由、预算说明、取舍和待核实信息。不合格或重复的云端候选逐项过滤；有效方案不足两项时展示明确标注的本地通用规划。 |
| 可折叠处理过程 | 展示意图识别、需求整理、人工修改、确认与生成等步骤，标明本地 LoRA、规则、云端模型或用户操作等来源及耗时。 |

任务状态会随房间保存和同步。刷新或服务重启可恢复需求卡片；中断的模型请求不会自动重放。取消、改动条件或新建任务会使旧请求失效，避免旧答案覆盖新需求。

## 使用示例

1. 在群聊发送：“今晚七点在北京三里屯吃川菜，人均100元，不吃花生。”
2. 需求卡片会提示补充人数。填写“3人”，也可修改预算。
3. 点击“保存需求”，再点击“确认并生成方案”。
4. 在右侧向下滚动，比较方案；展开“查看处理过程”查看来源和耗时。
5. 若要改时间，继续说“时间改成明晚七点，其他要求不变”，核对更新后的卡片再确认。
6. 仅需咨询时，输入问题并点击“询问 AI”。普通发送是否自动整理需求，由本群开关控制。
7. 安排结束后选择“标记为已完成”，或点击“开始新安排”。

## 验收结果

- 自动化检查：151 项 Python 测试、28 项前端测试，共 179 项通过。覆盖缺项、修改、冲突、取消、过时结果拦截、房间隔离、鉴权、持久化、前端草稿与异常显示等。
- 真实本地模型：GPU 加载 Qwen3 + LoRA；聚餐和出行样例正确识别并提取字段；确认前不生成推荐；普通聊天和取消场景未产生多余推荐。
- 真实云端调用：7 次受限测试请求均收到 qwen3.8-flash 响应，服务返回的总用量合计 3,264 tokens。部分早期方案未通过内容校验而进入本地备用流程，这不是 API 连接失败。
- 最终云端方案实测：返回三个不同方案，成功通过校验并在页面展示，处理记录显示“千问云端（结构校验）”，本次生成耗时约 6.4 秒。
- 主动问答实测：关闭自动识别后仍可调用云端回答订餐注意事项，原需求卡片保留。
- 浏览器实测：补人数、编辑预算、自然语言改时间、保存与确认、方案比较、折叠记录、刷新恢复、标记完成、开始新安排均验证。
- 正式服务：重新启动于 127.0.0.1:5000，本地模型使用 CUDA，云端配置加载成功。

真实模型及浏览器测试使用隔离测试账号和数据目录，未将合成测试聊天写入正式用户数据。代码修改前已留存备份，原账户、聊天记录、模型权重和加密凭据保留。

## 使用边界

当前方案是规划建议，尚未接入实时地图、餐厅营业状态、票价或余票查询，也不会实际预约或购票。页面会明确提示核验。自动识别整理目前主要覆盖吃饭和出行；普通问答通过云端模型完成。

上述测试证明这些样例和流程可运行，不代表在所有表达或多人聊天中都能识别正确。本次未开展大规模准确率评估或手机浏览器实机验收。
