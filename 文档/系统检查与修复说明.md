## 已修复的问题

| 原问题 | 修复后的行为 |
|---|---|
| 连续消息先触发推理和云端请求，再等待回复，容易重复调用 | 每个房间等待最后一条消息约 10 秒再开始推理；新消息替换待处理任务 |
| 旧推理结果可能在取消后仍发布 | 每个任务绑定独立版本，推理前后、生成前后和发布时检查；新增“停止本次回复” |
| 识别失败或识别为取消时无反馈 | 页面显示等待、识别、生成、取消、普通聊天和失败状态 |
| 模型偶发输出不符合约束，静默丢弃 | 仅结构校验失败时重试一次，仍失败则明确提示；不伪造或改写标签 |
| 粘贴多说话人对话被额外套上昵称，影响模型输入格式 | 已有多行说话人标签时保留原格式 |
| 切换房间后仍订阅旧房间，消息可能混入 | 后端退出旧房间；前端检查所有消息、历史、在线用户和 AI 状态的房间 |
| 刚进入房间时，历史加载可能覆盖先收到的新消息 | 历史加载前缓存新消息，随后按消息 ID 去重追加；同样保留先到的 AI 状态 |
| 发送失败仍可能清空输入，中文输入法确认可能误发 | 收到成功确认后才清空未变化的草稿；断线保留文字，识别输入法组合状态 |
| 客户端仅传用户名即可操作，存在冒充风险 | 登录签名令牌校验；发送、加入房间、改资料、停止回复和上传均校验身份 |
| 密码明文保存 | 新账号保存密码哈希；旧账号在成功登录时自动迁移，保留资料。尚未登录的旧账号未批量转换 |
| 消息、昵称、引用等直接拼接 HTML，存在脚本注入风险 | 改用 DOM 文本节点和事件绑定；拒绝可执行地址、SVG 等不支持附件 |
| JSON 读写并发导致覆盖风险 | 完整读改写事务加锁，临时文件写入后原子替换；失败保留旧记录 |

## 尚待改进的实际限制

1. 本次出行样例“明天上午从北京坐高铁去上海，预算六百元”正确识别为出行，但需求字段仍漏掉时间和预算。小模型的细节提取和复杂上下文泛化仍需更丰富的数据、单独的保留测试集和专项评估；这些小样本不能证明全面准确。
2. 已经发往云端的请求无法撤回；点击停止后结果不会发布，但该次调用可能仍有计费，同一房间的下一任务需等待旧请求结束。
3. 餐厅、车票等回复目前仍是非实时建议，没有接入真实库存、余票或实时价格查询。
4. 页面样式、Socket.IO 客户端和字体仍依赖 CDN；完全断网运行还需要将静态资源改为本地托管。
