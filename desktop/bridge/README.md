# AI 本地桥

桌面助手通过隐藏的 Python 子进程和标准输入/输出通信，不监听网络端口。原网页项目不会被修改，也不复制其 API 密钥或聊天数据。

## 运行要求

- 使用已安装网页依赖的 Python，可通过桌面程序的 `--python` 指定完整路径。
- `--web-root` 指向包含 `assistant_features.py`、`model_loader.py` 和 `tools/` 的网页代码目录。
- `--bridge-path` 指向本目录的 `assistant_bridge.py`。
- 本地意图模型继续读取网页项目的 `CHAPTER2_BASE_MODEL`、`CHAPTER2_LORA_PATH` 配置；未指定时沿用网页项目默认路径。模型只从本地加载，不自动下载。
- 千问凭据继续读取网页项目环境变量或 `.local` 内当前 Windows 用户的 DPAPI 加密密钥；不要将 `.local` 上传到 GitHub。

## 数据和行为

`AnalyzeAsync` 仅本地运行。默认用规则判断吃饭/出行并复用网页字段提取；勾选 LoRA 后，仅在线索不明确时尝试加载本地模型，第一次运行会较慢。LoRA 不可用时明确显示规则来源，不伪装为模型结果。

现有 LoRA 不能保证每次识别正确。明确的吃饭或出行线索直接采用规则并整理字段，不会因模型分歧卡住；模糊语句的模型判断只作参考。默认规则模式不依赖 LoRA，也不会把规则输出称为模型结果。

`ReplyAsync` 只应在用户确认本次上传文字后调用。最多发送最近 20 条消息，每条最多 2000 个 Unicode 字符，总计最多 8000 个字符。上传内容仅有 `self/other` 和文字；会话标识、联系人标题、消息 ID、截图不进入云端请求。未知发言方会阻止发送，需先校对。

群聊模式使用 `RecommendAsync`，在用户点击命名的千问推荐按钮，或明确开启自动云端推荐后调用。它遵守相同的 20 条 / 每条 2000 字 / 合计 8000 字限制；接受 `unknown` 未标注群消息，只要求画面已稳定，不要求知道每条消息是谁发的。云端只收到角色与文字，其他元数据会被去除。

群推荐返回需求汇总、2–3 个可比较的方案方向（标题、理由、代价或局限）和待确认事项，不返回个人回复草稿。没有有效安排或安排已取消时允许返回空方案。提示词要求保留不同群成员的约束与分歧，不从消息数推断人数，不把预算当实时价格。没有联网商家/票务检索能力，因此来源标注“未联网核实”；不编造具体商家、班次或完成预订的说法。输出只作为文本展示，额外动作/命令字段、缺字段或超限结构会被整体丢弃；格式验证不等于事实验证。

实际服务地址必须恰好为 `https://maas.qianwenaiapi.com/compatible-mode/v1`，模型必须为 `qwen3.8-flash`。不匹配界面说明的环境变量覆盖会被拒绝。生成失败会保留可见警告和本地推荐，不把本地模板标成千问结果。没有自动发送聊天消息的能力。

每个请求带单独 ID 和会话版本。取消会终止本助手启动的 Python 子进程；之后的请求会重新启动，旧响应不会混入新会话。取消已发出的云端请求不保证服务商停止计算或计费，但不会再展示其回复。

## 验证

```powershell
python -X utf8 -m unittest discover -s desktop/bridge -p 'test_*.py'
dotnet run --project desktop/bridge/service_check/ServiceCheck.csproj -c Release -- <python完整路径> <网页代码目录> <assistant_bridge.py完整路径>
```

固定合成聊天的实测脚本默认不调用云端：

```powershell
python -X utf8 desktop/bridge/live_check.py --web-root <网页代码目录> --lora
```

显式添加 `--live-cloud` 才会产生一次千问请求（可能计费）；脚本仅使用内置模拟聊天，不读取屏幕、联系人或历史消息。`--output <路径>` 可保存这份合成测试结果。
